DAILY INTELLIGENCE · SEP 12, 2026

Agents are becoming an enterprise runtime.

The freshest verified signals in this window point less to another frontier-model race and more to the infrastructure around agents: long-horizon execution, enterprise control planes, retrieval infrastructure, and the economics of making AI work reliably.

Research window: Sep 11, 10:00 AM → Sep 12, 10:00 AM ISTSignal: HighFocus: Agent infrastructure · Enterprise AI · Retrieval · Developer tooling

Research / intelligence

What actually changed

01 · Enterprise agents

Salesforce introduced job-ready Agentforce agents and a long-horizon runtime

Salesforce published a September 11 announcement for a portfolio of job-ready agents across sales, service, commerce, employee experience and back-office work. It says the new runtime lets agents pursue goals across days and weeks, with memory, durable execution and dynamic steering. Salesforce also says Multi-Agent Orchestration is generally available and Agent Optimizer is planned for October.

What matters: the product unit is shifting from an agent that completes a request to an agent that owns a goal over time. That creates a different engineering problem: persistent state, checkpoints, changing context, approvals and recovery become part of the runtime.

02 · Enterprise AI harness

Salesforce framed the enterprise AI harness as a control layer above individual agents

Salesforce introduced an Enterprise AI Harness organized around trusted context, agency, action, governance, security and models, alongside an AI Control Plane for identity, lifecycle, evaluation, observability and cost management across Salesforce and third-party AI.

What matters: this is a strong signal that enterprise agent architecture is moving toward a shared control plane rather than separate infrastructure for every agent. Treat Salesforce's design as a vendor architecture proposal, not proof that the category is solved.

Source: Salesforce announcement. Additional coverage timestamped Sep 11. citeturn10search0turn10search5

03 · Retrieval infrastructure

Elastic launched a serverless vector database aimed at removing RAG infrastructure work

Elastic announced Elasticsearch Vector Database on September 11 at 13:45 EDT. The serverless offering handles vector storage, indexing, embedding and hybrid retrieval with managed infrastructure, supports text, image and multimodal vectors, and uses Better Binary Quantization that Elastic says can reduce vector memory usage by up to 32x.

What matters: retrieval infrastructure is being pushed upward into managed defaults. The opportunity is no longer simply “build a vector database”; it is deciding how much retrieval infrastructure application developers should have to understand or control.

Source: Business Wire / Elastic, Sep 11, 13:45 EDT (17:45 UTC; 23:15 IST). citeturn11search5turn11search6

04 · Inference infrastructure

AWS added prefix-aware routing to SageMaker Inference

AWS introduced prefix-aware routing for real-time LLM inference endpoints. Requests sharing a prompt prefix can be routed to the same instance so prefix KV caches are reused. AWS reported up to 77% lower P50 time-to-first-token and up to 16% higher throughput in its Llama 3.1 70B benchmark, with routing overhead of 1.3–1.9 ms per request.

What matters: prompt caching is becoming a routing problem, not merely a model-serving optimization. The system deciding where a request runs can materially change latency and cost.

Source: AWS Machine Learning Blog; original event timestamped Sep 10, 21:58 UTC, inside today's window. citeturn9search0

Angle expansion

One story → many routes

Story 01 · Salesforce long-horizon agents

Understand / analyze

  • Explain why “agent that completes a task” and “agent that pursues a goal for weeks” are different system categories.
  • What most people may miss: durable execution is becoming as important as model intelligence.
  • Second-order implication: human work may shift from prompting agents to managing queues, exceptions and goal boundaries.

Opinion / ideas

  • Contrarian: the hard part of autonomous agents may no longer be reasoning; it may be maintaining correct state over time.
  • Debate: should an agent be allowed to keep pursuing a goal after the user stops interacting with it?
  • Prediction: long-horizon runtimes will become a standard primitive in agent platforms.

Build / experiment

  • 30 min: build a tiny goal loop that persists a task, state and next action in a database.
  • 60 min: add checkpoints and resume-after-failure behavior.
  • 90 min beginner build: create a “personal project agent” that remembers a goal, breaks it into tasks, marks progress and resumes tomorrow.
  • 1 day: build a miniature long-horizon runtime with memory, scheduled wake-ups, tool calls, approval gates and a kill switch.
  • Recreate the core idea with ordinary LLM calls instead of a specialized agent platform.

Test / verify

  • Compare stateless task agents against persistent agents on a multi-step project.
  • Remove persistent memory and measure failure/repetition.
  • Inject changed requirements midway through the task and measure whether the agent adapts safely.

Teach / apply

  • Architecture breakdown of memory + durable execution + steering.
  • Tutorial: build a resumable agent worker.
  • Business opportunity: “agent runtime as a service” for small companies that cannot build durable execution themselves.

Top routes: 90-minute build, persistent-agent experiment, long-horizon architecture breakdown, contrarian “state is the bottleneck” thesis, one-day miniature runtime.

Story 02 · Enterprise AI Harness

Understand / analyze

  • Explain the difference between an agent harness and an enterprise AI control plane.
  • What changed: identity, governance, model selection, context and observability are being positioned as shared infrastructure.
  • Surprising implication: the “agent platform” may become less important than the layer that controls all agents.

Opinion / ideas

  • Contrarian: enterprises should not build one perfect agent; they should build one trusted boundary around many agents.
  • Debate: should the model router be allowed to choose models but never permissions?
  • Prediction: agent identity and authorization will become as standard as API authentication.

Build / experiment

  • 30 min: create a central policy middleware for an agent.
  • 60 min: add budgets, allowed tools and approval rules.
  • 90 min beginner build: make a small “AI control plane” dashboard showing agent, model, tools, permissions and cost.
  • 1 day: build a multi-agent gateway with identity, audit logs, approval gates, spend limits and model routing.

Test / verify

  • Run three different agents through one shared control layer and compare operational complexity with three independent stacks.
  • Remove the central policy layer and deliberately test unsafe tool access.

Teach / apply

  • Architecture: context → identity → policy → model → action → audit.
  • Checklist for production agent governance.
  • Startup opportunity: lightweight agent control plane for SMBs.

Top routes: build the control plane, “harness around the agent vs harness around AI” thesis, architecture post, 90-minute governance dashboard.

Story 04 · AWS prefix-aware routing

Understand / analyze

  • Explain why identical prompt prefixes create a cache-locality problem.
  • What changed: the serving layer now routes requests based on cache affinity.

Opinion / ideas

  • Contrarian: model cost optimization increasingly belongs in the scheduler, not the prompt.
  • Prediction: agent runtimes will eventually optimize routing, cache locality and model selection together.

Build / experiment

  • 30 min: create a toy request router that groups identical prefixes.
  • 60 min: benchmark cache-hit vs cold requests.
  • 90 min beginner build: make a simple LLM gateway that tracks prompt-prefix frequency and routes repeated workloads to the same worker.
  • 1 day: compare naive round-robin routing with prefix-aware routing under a simulated agent workload.

Test / verify

  • Reproduce AWS's claimed latency effect on a smaller workload.
  • Vary prefix length, concurrency and request burstiness.
  • Test whether routing benefits survive when prompts diverge after the shared prefix.

Top routes: reproduce the cache-locality benchmark, “the scheduler is part of model economics,” and a 90-minute LLM gateway build.

What is worth pursuing now?

#1 · First-hand evidence

Build a miniature agent runtime in 90 minutes

#2 · Experimentation

Does prefix-aware routing actually make an agent cheaper and faster?

Build a tiny workload with repeated system/tool prefixes, compare naive routing against cache-aware routing, and publish measured latency, cache hit rate and cost. This converts infrastructure news into original evidence.

Formats: benchmark, technical post, chart carousel.

#3 · Building

Build your own tiny Enterprise AI Control Plane

Make one dashboard that registers agents, assigns permissions, sets spend limits, records tool calls and allows human approval. It is a concrete manifestation of the Salesforce architecture and directly fits your AI-harness positioning.

Formats: demo video, architecture post, open-source project.

What an agent actually needs to run for a week

Use the long-horizon runtime story to explain memory, durable execution, scheduling, state, recovery, observability and human intervention. This is a strong educational piece because it exposes the infrastructure hidden behind “autonomous agent.”

Formats: carousel, long-form post, architecture diagram.

Use Elastic's launch as the starting point for a practical comparison: what disappears when embeddings, indexing, hybrid retrieval and inference are managed for you, and what control you lose?

Formats: 90-minute build, comparison benchmark, tutorial.
